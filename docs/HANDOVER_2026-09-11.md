## 1. The build does not run in a git worktree, and the error does not say so

This round worked in `C:/bcwt/p5-overnight` per the shared-checkout rule. The first build failed
outright:

```
Failed to execute goal pl.project13.maven:git-commit-id-plugin:4.9.10:revision (default)
  Could not get HEAD Ref, are you sure you have some commits in the dotGitDirectory?
```

Nothing is wrong with the repository. In a linked worktree `.git` is a **file** pointing at the real
git directory, not a directory, and that plugin version cannot follow it. `failOnNoGitDirectory=false`
does not help, because the directory is found — it just cannot be read.

**Add `-Dmaven.gitcommitid.skip=true` to every Maven command run from a worktree.** It only skips
stamping build metadata; tests are unaffected. The full incantation used all night:

```
M=".../4399718c-9344-4d71-8df8-e23bd0de46db/scratchpad"
"$M/apache-maven-3.9.9/bin/mvn" -o -B -Dmaven.repo.local="$M/m2repo" \
  -Djacoco.skip=true -Dmaven.gitcommitid.skip=true \
  -Dtest='com.betterco.app.integration.kyc_com.**,com.betterco.app.aggregation.**' \
  -DfailIfNoSpecifiedTests=false test
```

Docker was deliberately not running, so no full-suite baseline was attempted and the "7 environmental
failures" figure is not quoted here. What was verified is the whole tree compiling (2809 sources) and
every affected package green.

## 2. Two things the plan had wrong, corrected before anything was built on them

1. **The reuse window would have been dead code where the plan put it.** The plan placed it in the
   ingestion worker. `ingestPass` skips every link outside `SourcePollPolicy.isWithinWindow`, and
   that schedule's last offset is `PT24H` — so a window measured in *days* can never fire there. It
   would have read correctly and never run. The window went into `AggregatedDocumentContentService`
   instead, the only place a stored copy is handed to a reader.

2. **Cross-customer reuse cannot be built at all yet, and the plan asked for it.** Serving customer
   A's document to customer B needs an identity for the *company* that survives across clients.
   There isn't one. `KycCaseLink` carries `jurisdiction` and `companyName` — a name is not an
   identity — and the vendor's document ids **repeat across cases and mean different things**, which
   is precisely why the acquisition index is client-scoped. D6, whether the vendor's licence even
   permits it, is also still unanswered. What was built is same-client freshness, which needs
   neither. **The missing key is the thing to decide before this goes further.**

## 4. Decisions taken that the documents did not settle

- **The reuse-window edge belongs to the fresh side.** Seven days old is not yet *older than* seven
  days.
- **A null `fetchedAt` counts as stale.** An age we cannot measure is not a freshness we can claim,
  and D1 says "reuse while fresh", not "reuse unless proven stale". It is the one input that resolves
  towards re-fetching rather than towards today's behaviour.
- **A source with no configured window never goes stale.** A missing window is an unanswered
  question, not an instruction to re-fetch on every read.
- **A failed refresh serves the stale copy**, not an error. A stale copy is still a copy.
- **Re-fetching is free but not free of consequence.** The source bills per case created, not per
  document read. What a refresh does cost is a *second stored document* — the previous file stays
  where it is, unreferenced. That is the orphaned-document problem (§5 #9) in a new place. It is
  logged rather than resolved, because deleting is irreversible and the retention decision says
  documents die with their client, not with a newer copy of themselves. **This is why the reuse flag
  is off by default.**
- **T4 turned the flag on nowhere.** Which environments get client creation is a person's call.
