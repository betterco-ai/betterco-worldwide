01 Authenticate

Exchange your key and secret for a token. It lasts one hour.

POST /auth/login
Content-Type: application/json

{ "key": "<your api key>", "secret": "<your api secret>" }

→ 200
{ "token": "<jwt>", "expiration": "2026-09-17T14:30:00Z", "refreshToken": "<token>" }

Send it on everything that follows as Authorization: Bearer <token>. Wrong credentials come back 400 "Credentials are invalid"; a missing or expired token, 401.

POST /auth/refresh-token returns a new access token and a new refresh token — the refresh token rotates, so store what comes back rather than re-sending what you just used.

Your workspaceId is issued once and appears in every path below. Keep the secret server-side; it is not for a browser.

02 Order a company

One call. You order a company, and the registry’s document set for it is what you get back.

POST /workspaces/{workspaceId}/document-search/cases

{
  "jurisdiction": "ES",
  "name": "CLOSER LOGISTICS SL",
  "legalType": "S.L.",
  "confirm": true,
  "idempotencyKey": "your-own-reference-0001"
}

→ 202 Accepted
{ "created": true, "processing": true,
  "caseId": "6a9fc02f5583c26b3129c874", "status": "pending" }

Store the caseId. It addresses everything afterwards.

Field
jurisdictionRequired. ISO code. GET …/document-search/jurisdictions lists where you can order.
nameRequired. The company name.
confirmRequired, and must be true. The order is billable and we will not place it on a maybe. Anything else returns 428 not_confirmed.
idempotencyKeyYour own reference. Re-send it and you get the same case back instead of a second, separately billed one. Send it on every create, not only on retries — a timed-out request whose order actually went through is exactly what it protects against.
legalTypeThe local legal form or its abbreviation — GmbH, S.L. Needed where the jurisdiction is not looked up automatically; we resolve the rest from it. Values: GET …/document-search/legal-forms?jurisdiction=ES.
companyTypeUse instead of legalType where that list is empty for your jurisdiction. Values: GET …/document-search/company-types. Send one or the other, never both.
externalCodeFrom a company look-up, if you did one — see below. Leave it out when entering the company by hand.
journeyNameOptional, defaults to All, and All is what you want unless we have agreed otherwise with you. It selects the document journey at the registry and we pass it through unvalidated, so an unagreed value is a quiet way to get a different set than you expected.

Optionally, find the company first

GET /workspaces/{workspaceId}/document-search/cases/search?jurisdiction=ES&query=CLOSER+LOGISTICS

Matches the company in the official registry so you start from a real record rather than typed-in text. Take externalCode from the result and pass it to the create call. Only automated jurisdictions can be searched — the automated flag on the jurisdictions list says which; elsewhere this returns 409 search_not_supported and you enter the details yourself.

What the order buys, and what it costs

The price is per case, not per document. Ten documents on a case cost the same as one, so anything that orders per document pays repeatedly for a set you already hold.

You cannot name the document you want: POST …/cases is the only write operation in this API area. What you can do is see in advance exactly what a jurisdiction returns, for free:

GET /workspaces/{workspaceId}/document-search/jurisdictions/GB/coverage

{ "code": "GB", "name": "United Kingdom",
  "sla": "25 minutes",
  "registries": ["Automated"],
  "baseDocuments": [
    { "type": "NEW_INCORPORATION", "description": "New Incorporation" } ],
  "additionalDocuments": [ ... ],
  "dataFields": { "companyIdentity": [...],
                  "controllingEntitiesAndIndividuals": [...],
                  "shareholdersPartnersAndUBOs": [...] } }

baseDocuments are provided as standard — that is what an ordinary order returns and what you can safely promise your own users. additionalDocuments are available on request and may cost extra; they are not selectable in the create call today, so if you need one routinely, talk to us rather than building around it.

Germany is refused, by design

A German company returns 409 jurisdiction_not_available, and nothing is created. BetterCo holds the German register directly, so ordering it here would buy something we already have. It is not an outage and re-sending will not help — route German companies the other way.

03 Wait for it

Poll the case until it is ready. Minutes to hours, depending on the registry.

GET /workspaces/{workspaceId}/document-search/cases/{caseId}

{ "caseId": "6a9fc02f…", "status": "building",
  "ready": false, "documentsStored": 2, "documentsTotal": 5 }
statusMeaning
pendingAccepted, not yet started at the registry.
buildingUnder way. Documents may already be listed — see section 04.
readyThe registry has finished and every document it produced is stored. readyAt carries when we observed it.
incompleteIt finished but could not produce everything asked of it.
failedThe order did not succeed. Retry with the same idempotencyKey.

documentsTotal can rise while the case is building, so read it as a running count rather than a target. ready is a convenience flag, true exactly when status is ready.

How long to expect is on the coverage endpoint as sla, per jurisdiction. Treat it as indicative: drive the loop from the case status, never from a timer.

04 Get the documents

List what the case produced, then download each one.

GET /workspaces/{workspaceId}/document-search/cases/{caseId}/documents

{ "caseId": "6a9fc02f…", "name": "CLOSER LOGISTICS SL", "documents": [
  { "documentId": "6a9fadce43675b6227c0f32c",
    "name": "CS01 Confirmation statement",
    "category": "Company Identity Documents",
    "roles": ["REGISTERAUSZUG", "GESELLSCHAFTERLISTE"],
    "status": "stored" },
  { "name": "Articles of association", "status": "pending" } ] }

Do not wait for the case to be ready before calling this. Documents are listed as soon as they are known, so you can show a reader what has arrived while the rest is still coming.

statusMeaning
storedWe hold the bytes. documentId is set and it can be downloaded.
pendingKnown but not yet retrieved. Keep polling. No documentId yet.
unavailableThe registry has no such document for this company.
failedRetrieval was attempted and did not succeed.

Download one

GET /workspaces/{workspaceId}/document-search/cases/{caseId}/documents/{documentId}/content

Returns the file as application/octet-stream. Each listed document also carries a ready-to-use downloadUrl, which is the same thing by another route. A document is scoped to its case: the right document id under the wrong caseId is a 404, not a document.

Which document is which

Registries title documents however they like. Where we can say what one evidences, it carries a role — and the role means the same thing in every jurisdiction, which makes it the field worth reading programmatically:

RoleAnswers
REGISTERAUSZUGThe register extract.
GESELLSCHAFTERLISTEWho the shareholders are.
GESELLSCHAFTSVERTRAGThe constitutional document.

roles is usually empty, and that is an answer rather than a gap: most documents evidence none of these three. A document can hold more than one — Britain’s CS01 is both the register extract and the shareholder list.

includePending is obsolete

Still accepted on these two endpoints, and ignored. There is one document list and one identifier space, so there is nothing to opt into. Existing callers do not break; new code should not send it.

The whole thing

05 End to end, in curl

The four calls above, in order, with nothing else in the way.

BASE=https://dev.betterco.ai/bcapi/restapi/v1
WS=<your workspace id>

# 01 — authenticate
TOKEN=$(curl -s -X POST "$BASE/auth/login" \
  -H 'Content-Type: application/json' \
  -d '{"key":"<key>","secret":"<secret>"}' | jq -r .token)

# 02 — order the company (billable, so confirm must be true)
CASE=$(curl -s -X POST "$BASE/workspaces/$WS/document-search/cases" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"jurisdiction":"ES","name":"CLOSER LOGISTICS SL","legalType":"S.L.",
       "confirm":true,"idempotencyKey":"demo-0001"}' | jq -r .caseId)

# 03 — wait for it
curl -s -H "Authorization: Bearer $TOKEN" \
  "$BASE/workspaces/$WS/document-search/cases/$CASE" | jq '.status, .documentsStored'

# 04 — get the documents
curl -s -H "Authorization: Bearer $TOKEN" \
  "$BASE/workspaces/$WS/document-search/cases/$CASE/documents" | jq .
curl -s -H "Authorization: Bearer $TOKEN" -o document.pdf \
  "$BASE/workspaces/$WS/document-search/cases/$CASE/documents/<documentId>/content"

To see your cases rather than one: GET /workspaces/{ws}/document-search/cases, with live status on each.

06 Identifiers — one change on your side

The only thing in this document that asks you to change existing code.

Cases and documents are addressed by BetterCo identifiers — 24 hexadecimal characters, opaque, not to be parsed. They are ours rather than any registry’s or supplier’s, because a case will not always be served from the same place, and an identifier belonging to one source cannot be the key you store.

In the case list, previouslyNow
caseCommonIdcaseId
statusNamestatus

This is a change of shape, not of format: code reading caseCommonId from the list reads undefined, and no translation layer absorbs that. If you hold an identifier durably anywhere, this is the point to migrate it.

There is a grace period, and it ends

For one release, the status, documents and download endpoints still accept the old numeric case number in place of caseId, so ids stored before the change keep working. The case list never returns it, and it will be removed.

07 Errors

One envelope everywhere. The machine-readable code is in message; error is only the HTTP reason phrase.

{ "error": "Conflict", "status": 409,
  "message": "jurisdiction_not_available",
  "timestamp": "2026-09-17T13:30:00" }
StatusmessageWhat it means
409jurisdiction_not_availableGermany — we source it directly. Route those companies the other way.
409search_not_supportedThis jurisdiction cannot be searched by name. Create the case directly.
428not_confirmedconfirm was not true.
422legal_type_or_company_type_requiredThis jurisdiction needs a legalType or a companyType.
422invalid_company_typeThe companyType sent is not an accepted value.
422organization_not_foundThe workspace has no organization to file the case under.
404case_not_foundNo such case in this workspace.
404document_not_foundNo such document — including a real document id under the wrong case.
404coverage_not_foundA supported jurisdiction with no coverage detail published yet.
502document_not_retrievableThe registry listed the document and then did not deliver it. Deliberately not a 404: the document exists, so calling it missing would hide a real gap in a compliance file.
503upstream_unavailableThe registry is not answering. Retry later.
504upstream_timeoutThe registry took too long. Retry later.

08 Every endpoint

Relative to https://dev.betterco.ai/bcapi/restapi/v1, all requiring Authorization: Bearer <token>. {ws} is your workspace id.

Method and pathReturns
POST /auth/loginToken, expiry, refresh token.
POST /auth/refresh-tokenA new token and a new refresh token.

09 What we need from you

1Who owns the identifier migration on your side, and whether the agreed date works for it.
2Whether you store case or document identifiers durably anywhere today. If you do, we should talk before the grace period ends rather than after.
3The jurisdictions you expect to order first, so we can confirm coverage and typical retrieval times for exactly those.

Anything unclear here is worth one message rather than a workaround. If the contract reads ambiguously to you, it is ambiguous, and we would rather fix it here than in your code.
