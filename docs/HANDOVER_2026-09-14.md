## 2. What has to be tested, in order

Cheapest and most informative first. Items 1–3 need nobody's permission; item 4 needs yours.

### T1 — Does it start at all? *(highest value, ~2 hours)*

Five branches have never started a JVM, and one change is exactly the shape that compiles and then
refuses to boot: **`p5/t3-reuse-window` adds `DocumentReusePolicy` as a new constructor dependency of
`AggregatedDocumentContentService`.** Spring wiring is the failure mode the P3 handover warns about
by name.

Launch with the Azure vars explicitly empty, or startup fails in a way that reads like a bean cycle
and is not:

```
export AZURE_CLIENT_ID= AZURE_USER_USERNAME= AZURE_USER_PASSWORD=
```

**Check startup POSITIVELY.** The obvious negative grep is not diagnostic — `UnsatisfiedDependency
Exception` matches any bean failure, most unrelated:

```
grep -c "Started Application in" <log>      # expect exactly 1
```

Only if that is 0 is the exception worth reading, and then read the **bean name**, not the type.

### T3 — A real full-suite baseline *(needs Docker running)*

**Start Docker Desktop first.** Without it, 14 test classes using `MongoTestContainer` die at class
construction with `ExceptionInInitializerError`, which reads nothing like a Docker problem. The "7
environmental failures" baseline in older notes is **only true with Docker up** — do not quote it
otherwise.

Running Maven from a **git worktree** needs one extra flag or the build fails before compiling:

```
-Dmaven.gitcommitid.skip=true
```

`git-commit-id-plugin` 4.9.10 cannot read HEAD through a worktree's `.git` *file*. The error names
the dotGitDirectory and nothing about worktrees.

### T4 — The one billable order *(needs explicit permission — do not do this unasked)*

This is the only test that can answer four open questions at once, and no amount of sandbox work
substitutes for it:

1. **Does a real registry PDF survive the pipeline?** Every sandbox file is the same 904-byte stub.
   The pipeline is proven; carrying a real document is not.
2. **P4's exit criterion** — "ten documents, one charge". Unprovable without a real multi-document
   case.
3. **The live status vocabulary.** `caseReadyDatetime` is stamped at creation on sandbox and at
   completion on live; anything status-shaped needs one confirmation against the live vendor.
4. **Real timings**, against the ~25 min / ~40 min / ~24 h figures quoted to Septeo.

Reads on production are free. **Creating a case is not.** Ask first, every time.
