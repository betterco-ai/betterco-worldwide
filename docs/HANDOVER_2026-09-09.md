## 2. Six things the plan had wrong, corrected before anything was built on them

This is what O1 was for. In descending order of how much damage each would have done:

1. **The billable moment is not where the plan put it.** The plan said to record cost at
   `buildPendingLink`. That runs *before* the POST, and an order the vendor rejects buys nothing —
   recording there would have invented spend out of every upstream outage. Cost is stamped inside
   `completeCreate`, past the line the code itself marks as *"the vendor HAS created a case and will
   bill for it"*.
2. **A price table already existed in the backend.** `KycPriceBands` over
   `src/main/resources/kyc/price-bands.csv` (132 rows: code, band, priceUsd), already injected into
   `KycGatewayService` and already published on the jurisdiction listing. The plan's fallback —
   record `UNKNOWN` and import nothing — was unnecessary.
3. **`orderedAt` and the ordering actor already exist.** `AuditMetadata` gives every link `createdAt`
   and `createdBy`. What was genuinely missing is `chargedAt`, which is a *different instant*: on a
   retried link `createdAt` is the first attempt.
4. **`contentDate` is already plumbed all the way to storage.** `DocumentIngestor` passes it into
   `UploadData.documentDate`. So the fix was one line at the point the acquisition is built, and the
   payoff is bigger than the plan claimed: stored documents now carry their filing date into document
   management, not just the acquisition row.
5. **The vendor world is already resolved in one place.** `KycVendorTargetResolver` honours
   `kyc-com.target` and falls back to the base url. O2 asks it rather than re-parsing the url, so
   there is still exactly one place that decides.
6. **The date format is established, not assumed.** `DocumentRoles` already strips
   `<\d{2}/\d{2}/\d{4}>` to match labels against real vendor data, and the measured labels include
   `<13/01/2026>` and `<17/12/2025>` — first component cannot be a month. Day-first is evidence, not
   a guess.

## 3. Decisions taken that the documents did not settle

Each is deliberate, reversible, and argued in the commit message it belongs to.

- **The recorded cost is named as a LIST PRICE** (`KycCostSource.LIST_PRICE_CONFIGURED`), not an
  invoiced amount. This matters right now: `price-bands.csv` still holds the **old** list —
  18.00 / 43.50 USD — and the vendor repriced on **26 August** to 19 / 49 / 89 / 119 USD, with BR, LU
  and IL changing band. An unlabelled number would have made a stale figure look authoritative.
  **The CSV wants refreshing; that is a data change, not a code one, and it is now an open item.**
- **A sandbox order records `NOT_BILLABLE`**, not a price. The sandbox is a free trial; pricing it
  would put money that was never spent into whatever reads the field later. An *unrecorded* world
  records `UNKNOWN` rather than defaulting to production — the same reasoning in reverse.
- **The order that least tolerates a missing cost is the one we could not record.** The vendor
  created a case, it will be invoiced, and we do not know which case it is. That path now records
  cost too; the *rejected* path still records none.
- **O5 is keyed on the vendor world, not on emptying the property per profile.** The plan proposed
  blanking `kyc-com.user.base-url` in the development profile. That would also disable the path for a
  dev box deliberately pointed at the production world — which is free, legitimate, and exactly how
  case 189's missing `businessRelationId` is meant to be investigated (§5 #7). With the world as the
  key, that case keeps working and the sandbox one stops lying. **No sandbox portal URL was
  invented; whether one exists is still unverified.**
- **O6's deny list fails CLOSED** — `document-search.deny-jurisdictions=DE` is the default in
  `application.properties` and has to be emptied deliberately. The failure mode of forgetting it is a
  bill. It is configuration rather than a constant so it can be widened without a code change.
- **O2 does not invert the vendor-config default.** Inverting it is right in shape but nobody has
  confirmed production runs with its profile active; if it does not, inverting takes production
  ordering down. An assertion can only ever *block* a money-spending configuration, which is why
  that half was safe to add unattended. **The inversion is still open and still needs a person.**
