## 2. Four things found, none of them by reading the plan

1. **`UploadData`'s validation is inverted** — it accepts any string and rejects legitimate
   ID-document types. This is how the `custom_<epoch>` types in F4 reached production data. Filed as
   **BCP-8429**. Not ours to fix; it sits under every uploader in the codebase.
2. **Deleting a client orphans its documents.** `deleteAllClientInfo` deletes neither company nor
   process documents, while its sibling `deleteAdvisorRelatedClientInfo` deletes both, and
   `ActorDeletionManager` covers neither. That contradicts D1 and is a data-retention question.
   **Recorded, deliberately not fixed** — the asymmetry looks deliberate enough to ask about, and a
   document delete is irreversible if that reading is wrong. Wants a ticket.
3. **An NPE in the unknown-source path** (`Map.of()` rejects a null key rather than returning null),
   found by a test written for a safety path nobody would exercise by hand.
4. **A design error of mine, caught by tests**: on discovering that storage would not return a
   document we had recorded as stored, the first version re-ingested it — a reader triggering a
   fresh multi-megabyte upload of a file storage had just rejected, on every read. It now serves
   from the source and leaves re-ingestion to the worker.

I also got one verification **wrong**: N1 reported "tests green" from stale surefire reports while
the fixture had never compiled. Caught in N2. Verification now reads the build result, never the
report files.

## 3. What the live order taught the design

The $18 spent on TATE & LYLE (case `189`) shaped four decisions that the sandbox could not have:

- **Documents arrive during the build, not at the end.** Seven were downloadable at 50% complete and
  the case was *still* not ready four hours later. So the worker is driven by the document list, via
  `includePending=true`, and never waits for case-ready.
- **Real files are megabytes** — a single 1903 incorporation document was 2.1 MB. Sizing anything
  against the sandbox's uniform 904-byte stubs would have been wrong.
- **Failure is per document.** Exactly one of that case's seven fails. One document must never cost
  a case the other six.
- **The content type must be set explicitly** — the server does not sniff, and a wrong one leaves
  the reviewer with a file the browser will not preview.
